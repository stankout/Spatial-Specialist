## 1. Purpose

This document defines the high-level operating model of AC Spatial Specialist.

It describes how strategy, operations, services, content, technology, customers, and approval responsibilities fit together.

Detailed responsibilities belong in ROLES_AND_AUTHORITY.md.

Detailed repeatable procedures belong in SOPs.

---

## 2. Operating Principle

AC should operate through documented systems rather than depending on undocumented owner memory.

The intended progression is:

DIRECTION
→ PLAN
→ ASSIGN
→ EXECUTE
→ REVIEW
→ APPROVE
→ PUBLISH / DELIVER
→ MEASURE
→ IMPROVE

Not every action requires Owner intervention.

Owner involvement should be concentrated where authority, risk, strategy, public claims, money, credentials, or irreversible decisions justify it.

## 5. Owner Dependency Reduction

The long-term objective is not to remove the Owner from the company.

The objective is to prevent routine execution from requiring constant Owner intervention.

The system should gradually allow delegated staff to:

- execute approved workflows
- prepare drafts
- manage routine communication
- organize content
- maintain records
- coordinate schedules
- monitor operational queues

while reserving defined decisions for Owner approval.

---

## 6. Work Classification

Work should generally fall into one of four classes.

### ROUTINE

Existing approved process.

Example:
Updating a content draft.

May be delegated.

### REVIEWABLE

Work may be executed by staff but requires review before becoming public or final.

Example:
New advertisement copy.

### CONTROLLED

Work changes business behavior, risk, money, authority, or public claims.

Example:
Changing service pricing architecture.

Requires designated approval.

### STRATEGIC

Work changes company direction.

Example:
Activating a new service.

Owner authority required.

---

## 7. Documentation Principle

Repeatable work should gradually become documented.

Not every tiny action deserves an SOP.

Create an SOP when:

- work repeats
- errors are costly
- another person may perform the work
- quality must remain consistent
- approvals matter
- important records must be retained

---

## 8. Operating Feedback Loop

AC should gradually operate through:

ACTIVITY
→ DATA / OBSERVATION
→ REVIEW
→ DECISION
→ PROCESS CHANGE

Examples:

Leads
→ conversion observations
→ improve qualification

Content
→ performance observations
→ improve format/topic strategy

Customer issues
→ recurring problem
→ improve SOP

Website
→ usage/error data
→ improve platform

---

## 9. Source of Truth

Company operations should use canonical repository documentation for durable policy.

Studio and future operational systems may become the source of truth for transactional records such as:

- leads
- bookings
- customers
- content objects
- media objects
- product records

Canonical policy documentation and operational records serve different purposes.

---

## 10. Current Stage

AC is currently transitioning from owner-centered operation toward documented system-centered operation.

The documentation system, Studio, roles, workflows, and future automation should support that transition without creating unnecessary bureaucracy.
